# SPEC-054 — Шаблоны опций товара с надбавками

## Цель

Редактор создаёт в Administration переиспользуемый шаблон опций (например,
«Материал» и «Цвет» фабрики) и назначает его многим товарам сразу через
динамические группы товаров (product streams) либо вручную конкретному товару.
Покупатель на карточке товара выбирает значение каждой опции из палитры
(картинка или цвет). Значение может менять цену товара фиксированной суммой
(«+200 €») или процентом от базовой цены («+20 %»). Выбор и надбавка
сохраняются в корзине и заказе.

## Границы

Входит:

- плагин `JvProductOptions`: сущности шаблонов, групп опций, значений и
  назначений;
- определение действующего шаблона товара;
- Store API route с опциями товара и рассчитанными надбавками;
- расчёт цены позиции корзины с учётом выбранных значений;
- снимок выбора и надбавок в payload позиции заказа;
- Administration: управление шаблонами, ручное назначение шаблона товару и
  просмотр выбранных опций/надбавок в позиции заказа;
- отображение выбранных опций и надбавок в стандартных письмах заказа и
  сгенерированных документах Shopware;
- DAL-валидация записи шаблонов.

Не входит:

- надбавка в листинге, сортировке и фильтре по цене; цена в листинге остаётся
  базовой ценой товара;
- свободный ввод значения покупателем: выбираются только значения шаблона;
- назначение шаблонов импортами OKB/AfterCool (SPEC-012, SPEC-013); импорт
  может позже назначать шаблон ручным назначением или через product streams;
- Shopware variants, configurator settings и properties: шаблон их не
  создаёт и не изменяет.

## Сценарий

1. Редактор создаёт шаблон, группы опций и значения с надбавками.
2. Редактор назначает шаблон динамическим группам товаров (например, «Все
   товары производителя X») и/или вручную отдельным товарам.
3. Next.js запрашивает опции товара через Store API и показывает палитру с
   надбавками; значение по умолчанию выбрано заранее.
4. Покупатель добавляет товар в корзину штатным
   `POST /store-api/checkout/cart/line-item` с выбором в payload.
5. Корзина рассчитывает цену позиции: базовая цена + сумма надбавок.
6. При оформлении заказа выбор и надбавки сохраняются в payload позиции заказа.
   Покупатель видит выбранные значения и доплаты в стандартном письме заказа и
   документах Shopware; сотрудник — в строке товара в Administration.

## Данные

### Сущности

Все сущности принадлежат плагину `JvProductOptions`. Названия переводимые
(translation-таблицы Shopware, fallback на системный язык).

`jv_option_template`:

| Поле | Тип | Правило |
|---|---|---|
| `id` | UUID | PK |
| `name` | translated string | обязательно |
| `active` | bool | по умолчанию `true` |
| `priority` | int | по умолчанию `0` |

`jv_option_template_group` — группа опций («Материал»):

| Поле | Тип | Правило |
|---|---|---|
| `id` | UUID | PK |
| `templateId` | FK → `jv_option_template` | обязательно, CASCADE |
| `name` | translated string | обязательно |
| `position` | int | порядок в шаблоне |
| `defaultValueId` | FK → `jv_option_template_value`, nullable | SET NULL; значение этой же группы |
| `paletteMediaId` | FK → `media`, nullable | SET NULL; общая палитра/референсное изображение группы (материал, цвет, размер и т.п.) |

`jv_option_template_value` — значение опции («Кожа Anthrazit»):

| Поле | Тип | Правило |
|---|---|---|
| `id` | UUID | PK |
| `groupId` | FK → `jv_option_template_group` | обязательно, CASCADE |
| `name` | translated string | обязательно |
| `position` | int | порядок в группе |
| `mediaId` | FK → `media`, nullable | SET NULL; картинка палитры |
| `colorHex` | string, nullable | `#RRGGBB`; используется, если нет картинки |
| `surchargeType` | `fixed` \| `percentage` | обязательно |
| `surchargePrice` | Shopware `PriceField` (JSON), nullable | обязательно при `fixed` |
| `surchargePercentage` | float, nullable | обязательно при `percentage`, `0 ≤ x ≤ 1000` |

`jv_option_template_product_stream` — M:N шаблон ↔ `product_stream`.

`jv_option_template_product` — ручное назначение: PK
(`product_id`, `product_version_id`), `template_id`. У товара не больше
одного ручного назначения. Удаление товара или шаблона удаляет назначение.

Значение без надбавки задаётся как `fixed` с ценой `0`.

### Payload позиции корзины

Запрос добавления (штатный route):

```json
{
  "items": [{
    "type": "product",
    "referencedId": "<productId>",
    "quantity": 1,
    "payload": {
      "jvOptionSelections": { "<groupId>": "<valueId>" }
    }
  }]
}
```

`jvOptionSelections` — объект «id группы → id значения». Группы, которых нет
в запросе, получают значение по умолчанию.

После расчёта корзина пишет в payload позиции `jvProductOptions`, и этот
снимок переходит в `order_line_item.payload`:

```json
{
  "templateId": "<id>",
  "baseUnitPrice": 1000.0,
  "surchargeUnitPrice": 400.0,
  "selections": [{
    "groupId": "<id>", "groupName": "Material",
    "valueId": "<id>", "valueName": "Leder",
    "surchargeType": "percentage", "surchargePercentage": 20.0,
    "surchargeUnitAmount": 200.0
  }]
}
```

Порядок `selections` — по `position` группы. Имена берутся на языке контекста
на момент расчёта. Суммы указаны в валюте и налоговом режиме (gross/net)
контекста.

`jvProductOptions` — канонический неизменяемый snapshot. Для совместимости со
штатным отображением вариаций Shopware в Administration, почтовых шаблонах и
PDF в тот же payload также записывается `options`: по одной паре `group` /
`option` на выбор. `option` содержит название значения и рассчитанную
надбавку в валюте контекста; для процентной надбавки показываются и процент,
и рассчитанная сумма. Существующие `payload.options` штатных вариантов
сохраняются и не заменяются. Повторный расчёт не дублирует пары опций.

Store API корзины, ответа оформления заказа и чтения заказа для авторизованного
покупателя возвращает оба поля в payload позиции. Стандартные шаблоны писем и
документов Shopware, которые выводят `payload.options`, показывают выбранные
опции вместе с надбавками. Admin order line-item grid использует то же поле.

## Правила

### Действующий шаблон товара

1. Шаблоны с `active = false` и шаблоны без групп не учитываются.
2. Если у товара есть ручное назначение на учитываемый шаблон, используется он.
   Вариант без собственного назначения наследует назначение родителя.
3. Иначе среди учитываемых шаблонов, назначенных хотя бы одной из групп
   `product.streamIds` товара (для варианта с наследованием от родителя),
   выбирается шаблон с наибольшим `priority`; при равенстве — с меньшим `id`.
4. Иначе у товара нет шаблона.

Принадлежность товара к группам берётся из штатного `product_stream_mapping`,
который обновляет Shopware.

### Надбавка

- Базовая цена — цена за единицу, которую Shopware рассчитал для позиции
  (включая расширенные цены по количеству), до промоакций.
- `fixed`: сумма для валюты контекста из `surchargePrice`; если для валюты нет
  отдельной цены — цена в валюте по умолчанию × `currency.factor`. Берётся
  `gross` или `net` по налоговому режиму контекста.
- `percentage`: `базовая цена × surchargePercentage / 100`. Процент считается
  только от базовой цены, не от других надбавок.
- Каждая надбавка округляется по `itemRounding` валюты контекста; итоговая цена
  за единицу = базовая цена + сумма округлённых надбавок.
- Налог позиции считается от итоговой цены по налоговому правилу товара.
- Промоакции применяются к итоговой цене позиции.

### Выбор

- У каждой группы шаблона должно быть значение: из `jvOptionSelections` либо
  значение по умолчанию.
- Выбор недействителен, если группа не принадлежит действующему шаблону,
  значение не принадлежит группе, ключ или значение — не UUID, или для группы
  без значения по умолчанию значение не выбрано.
- У товара с шаблоном без `jvOptionSelections` применяются значения по
  умолчанию; если у какой-либо группы его нет, выбор недействителен.
- `jvOptionSelections` у товара без шаблона делает выбор недействительным.
- Позиция с недействительным выбором удаляется из корзины, и в корзину
  добавляется ошибка `jv-product-options-invalid-selection` (уровень error,
  параметр `lineItemId`). То же происходит при пересчёте, если шаблон или его
  значения изменились и сохранённый выбор стал недействительным.
- Один товар с разным выбором — разные позиции корзины. При наличии
  `jvOptionSelections` id позиции определяется детерминированно по id товара и
  выбору (после подстановки значений по умолчанию), id из запроса не
  используется. Повторное добавление того же выбора увеличивает количество
  существующей позиции.
- Изменение `jvOptionSelections` через `PATCH /store-api/checkout/cart/line-item`
  разрешено; позиция пересчитывается, id не меняется.

### Валидация записи

При любой DAL-записи (Admin API, Administration, импорт):

- `fixed` требует `surchargePrice` с ценой для валюты по умолчанию, `gross` и
  `net` ≥ 0, и не допускает `surchargePercentage`;
- `percentage` требует `surchargePercentage` в диапазоне `0…1000` и не
  допускает `surchargePrice`;
- `colorHex` соответствует `^#[0-9A-Fa-f]{6}$`;
- `defaultValueId` ссылается на значение той же группы.

Нарушение отклоняет запись штатной ошибкой валидации DAL с путём поля.

## Store API

`POST /store-api/jv-product-options/{productId}`

Возвращает опции действующего шаблона для товара в текущем sales channel
context. Товар должен быть доступен в sales channel, иначе штатная ошибка
`CONTENT__PRODUCT_NOT_FOUND` (404).

```json
{
  "apiAlias": "jv_product_options",
  "productId": "<id>",
  "templateId": "<id>",
  "baseUnitPrice": 1000.0,
  "groups": [{
    "id": "<id>",
    "name": "Material",
    "position": 1,
    "defaultValueId": "<id>",
    "paletteMedia": { "url": "https://…", "alt": "…" },
    "values": [{
      "id": "<id>",
      "name": "Leder",
      "position": 1,
      "media": { "url": "https://…", "alt": "…" },
      "colorHex": null,
      "surcharge": {
        "type": "percentage",
        "percentage": 20.0,
        "unitAmount": 200.0
      }
    }]
  }]
}
```

- `baseUnitPrice` и `unitAmount` рассчитаны для количества 1 по тем же правилам,
  что и в корзине; `percentage` равно `null` для `fixed`.
- Без шаблона: `templateId: null`, `groups: []`, `baseUnitPrice` заполнен.
- Группы и значения отсортированы по `position`, затем по `id`.
- `media` равно `null`, если картинки нет.
- `paletteMedia` равно `null`, если у группы нет общей палитры/референсного изображения.
- `paletteMedia` является общим визуальным источником группы; `values[].media` остаётся
  необязательным изображением конкретного значения.

Frontend показывает итоговую цену как `baseUnitPrice` + сумма `unitAmount`
выбранных значений. Цена в корзине остаётся определяющей.

## Ошибки и повтор

- Расчёт корзины детерминирован и повторяем: повторный пересчёт той же корзины
  даёт ту же цену и тот же снимок.
- Изменение шаблона не меняет уже созданные заказы: заказ хранит снимок.
- Удаление значения по умолчанию обнуляет `defaultValueId` группы.

## Изменения Shopware

- Новый плагин `custom/static-plugins/JvProductOptions` (`jvmoebel/product-options`,
  namespace `Jv\ProductOptions`), подключается в корневом `composer.json`.
- `Core/Content/OptionTemplate/`: definitions, entities, collections, translation
  definitions; `OptionTemplateEntity`, `Aggregate/OptionTemplateGroup/OptionTemplateGroupEntity`,
  `Aggregate/OptionTemplateValue/OptionTemplateValueEntity`.
- Extension `product` → ручное назначение шаблона (для Administration).
- Миграция схемы с translation-таблицами и внешними ключами.
- `Service/OptionPricing/`:
  - `OptionSurchargeCalculator` — сумма надбавок за единицу;
  - `FixedSurchargeAmountResolver` — сумма `fixed` для валюты и налогового режима;
  - `OptionSelectionResolver` — проверка выбора и подстановка значений по умолчанию;
  - `OptionTemplateResolver` — действующий шаблон товара;
  - `OptionLineItemIdGenerator` — детерминированный id позиции по товару и выбору.
- Cart collector/processor с приоритетом ниже `ProductCartProcessor` (5000) и
  выше промоакций (4900).
- Декоратор фабрики product line item для детерминированного id позиции.
- DAL validation subscriber для правил записи.
- Store API route `jv-product-options`.
- Administration: модуль «Optionsvorlagen» (список, шаблон, группы, значения
  с картинкой, цветом и надбавкой, назначение product streams), поле
  «Optionsvorlage» в карточке товара; snippets `de-DE` и `en-GB`.

## Проверка

Автоматические тесты:

- unit: расчёт `fixed`/`percentage`, процент только от базовой цены,
  округление, пересчёт `fixed` по курсу валюты, gross/net;
- unit: выбор — значения по умолчанию, чужая группа, чужое значение, не UUID,
  группа без значения по умолчанию;
- integration: действующий шаблон — ручное назначение, product stream,
  priority, неактивный шаблон, наследование варианта;
- integration: Store API контракт, в том числе товар без шаблона;
- integration: цена позиции корзины, разные выборы как разные позиции,
  недействительный выбор с ошибкой корзины, снимок в `order_line_item.payload`;
- integration: DAL-валидация записи.

Ручная приёмка в Administration и через Store API:

1. Создать шаблон «Материал» (Stoff — `fixed` 0 по умолчанию, Leder —
   `percentage` 20, картинки палитры) и «Farbe» (Grau — по умолчанию,
   Rot — `fixed` 50 €, colorHex).
2. Назначить шаблон динамической группе по производителю; проверить, что Store
   API отдаёт опции для товара этого производителя и не отдаёт для другого.
3. Добавить товар в корзину на рынке в EUR и в другой валюте; проверить цену
   позиции и пересчёт `fixed` по курсу.
4. Добавить тот же товар с другим выбором: две позиции.
5. Оформить заказ и проверить снимок в payload позиции заказа.
6. Поменять надбавку в шаблоне: новая корзина пересчитана, заказ не изменился.
7. Проверить ответ `POST /store-api/checkout/order` и чтение заказа через Store
   API: `payload.jvProductOptions` содержит структурированный snapshot, а
   `payload.options` — отображаемые названия и доплаты.
8. Открыть заказ в Administration и проверить каждую выбранную опцию и её
   доплату; проверить отображение тех же данных в стандартном письме заказа и
   сгенерированном PDF-документе.
