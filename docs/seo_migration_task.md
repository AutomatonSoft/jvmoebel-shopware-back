Реализовать backend-часть SEO-миграции CosmoShop → Shopware

Цель

Реализовать первую рабочую версию переноса SEO-данных CosmoShop в Shopware и подготовить данные, необходимые Next.js и инфраструктуре для сохранения старых публичных URL после переключения сайта.

Первую полноценную реализацию и проверку выполнить для jvmoebel.de. Решение сразу проектировать так, чтобы затем использовать его для остальных Sales Channels без отдельной реализации под каждый магазин.

Техническую структуру, модель хранения, формат промежуточных данных и набор команд разработчик определяет самостоятельно. Перед реализацией нужно изучить фактические данные CosmoShop и зафиксировать выбранный подход в спецификации рядом с кодом.

Что необходимо реализовать

1. Получение SEO-данных CosmoShop

Определить и реализовать извлечение доступных SEO-данных для:

товаров;

старых категорий;

CMS, информационных и служебных страниц;

изображений и других индексируемых media.

Использовать фактические источники CosmoShop: базу данных, SEO-таблицы, URL keys, sitemap, файлы и другие необходимые источники, обнаруженные при обследовании.

Для каждой исходной записи должна сохраняться её принадлежность конкретному магазину и исходный идентификатор, чтобы данные разных доменов не смешивались.

2. Перенос SEO товаров в Shopware

Перенести доступные и релевантные SEO-данные товаров, включая:

существующий публичный URL или информацию, позволяющую его восстановить;

robots/noindex, если настройка существовала;

связанный SEO-контент, который относится к товару;

SEO должно храниться в контексте правильного Sales Channel и языка.

Старый товарный URL по возможности должен продолжить открывать тот же товар с 200. Если это невозможно, система должна подготовить однозначное решение для последующего 301 на новый канонический URL.

Товар нельзя автоматически считать тем же самым только из-за совпадения EAN. Нужно использовать уже принятую модель идентичности и происхождения импортированных товаров. Неоднозначные случаи не объединять молча.

3. Обработка старых категорий

Целевое дерево категорий отличается от дерева CosmoShop. Старые категории не нужно импортировать как второе дерево Shopware и не нужно добавлять их в новую навигацию ради сохранения SEO.

При этом необходимо:

извлечь старые category URL и доступные SEO-данные;

сопоставить старые категории с новым проектным деревом там, где соответствие можно определить надёжно;

учитывать не только название категории, но и её назначение, путь и состав товаров;

предусмотреть возможность ручного решения для неоднозначных случаев;

не выбирать фиктивную новую категорию, если релевантного соответствия нет;

подготовить результат, по которому старый URL можно сохранить как отдельную landing page, перенаправить на новую категорию либо закрыть без замены.

Разработчик самостоятельно проектирует механизм автоматического и ручного сопоставления. По итогам запуска должно быть видно, какие категории сопоставлены автоматически, какие требуют решения и почему.

4. CMS и другие индексируемые страницы

Проверить фактически существующие CMS, информационные, юридические и служебные страницы CosmoShop.

Для страниц, которые продолжают существовать, перенести доступные SEO-поля и сохранить связь с прежним URL. Для страниц, которые нельзя перенести автоматически, сформировать понятный результат для ручного решения.

Не переносить устаревший юридический или служебный контент как актуальный без отдельного подтверждения, но и не терять сведения о его существующем URL.

5. Старые URL изображений

Собрать связь между:

старым публичным URL изображения;

фактическим исходным файлом;

исходным товаром или страницей;

соответствующей media-записью Shopware, если она уже создана.

Подготовить воспроизводимый результат, позволяющий инфраструктуре сохранить старые индексируемые URL изображений после отключения CosmoShop.

Физически одинаковые изображения не должны терять свои старые публичные URL. Отсутствующие и повреждённые файлы нужно выводить в отчёт, а не заменять автоматически нерелевантным изображением.

Размещение файлов и настройка публичной раздачи могут выполняться отдельной инфраструктурной задачей, но backend-реализация должна предоставить все необходимые данные и понятный контракт для этой работы. В целом подумать про то как сделать это учитывая что картинки будут в S3

6. Результат обработки старых URL

Реализация должна формировать воспроизводимый результат для старых URL, достаточный для последующей настройки Next.js и инфраструктуры.

Для каждого обнаруженного старого URL должно быть понятно:

URL сохраняется и должен отдавать существующую страницу;

URL должен вести на подтверждённую новую страницу;

требуется отдельная landing page или ручное решение;

релевантной замены нет;

URL не удалось определить автоматически и требуется проверка.

Конкретный формат и способ хранения результата выбирает разработчик. Он должен быть машиночитаемым, повторяемым и пригодным для использования в следующих задачах без ручного разбора логов.

Не выполнять массовый redirect старых страниц на главную и не подбирать нерелевантную цель только ради наличия redirect.

7. Интеграция с Shopware и Next.js

Проверить, какие данные уже доступны через штатные механизмы Shopware SEO URL и Store API, и не создавать дублирующую систему без необходимости.

Если штатных данных недостаточно для headless storefront, реализовать минимально необходимое backend-расширение либо подготовить согласованный контракт для Next.js.

По завершении должно быть документировано:

как Next.js определяет сущность по публичному пути;

откуда Next.js получает title, description, robots и другие SEO-данные;

как определяется канонический URL конкретного Sales Channel;

какие старые URL обрабатывает приложение, а какие инфраструктура;

какие данные нужны frontend-разработчику для sitemap, canonical, hreflang, structured data и корректных HTTP status.

Frontend-реализация Next.js в эту задачу не входит, но задача не считается завершённой без пригодного для неё backend-контракта и примеров.

8. Повторный запуск и отчётность

SEO-миграция должна быть безопасной для повторного запуска.

Повторный запуск не должен:

создавать дубли SEO URL или служебных записей;

смешивать Sales Channels;

молча перезаписывать вручную исправленные данные;

превращать ранее неоднозначное сопоставление в случайное автоматическое решение;

удалять уже существующие связи без явной причины.

После запуска предоставить отчёт минимум по следующим группам:

обработанные товары;

обработанные старые категории;

обработанные CMS/служебные страницы;

найденные старые media URL;

успешно перенесённые SEO-поля;

сохранённые старые URL;

подготовленные перенаправления;

случаи для ручной проверки;

отсутствующие исходные данные;

ошибки обработки.

Проверки

Реализацию покрыть автоматическими тестами минимум для сценариев:

перенос SEO товара в правильный Sales Channel и язык;

повторный запуск без дублей;

одинаковый исходный ID из разных магазинов не смешивается;

одинаковый EAN сам по себе не объединяет разные товары;

старый URL корректно связывается с целевой сущностью;

категория сопоставляется с новым деревом;

неоднозначная категория остаётся на ручную проверку;

отсутствие подходящей категории не создаёт фиктивное сопоставление;

отсутствующий или повреждённый media-файл попадает в отчёт;

вручную изменённые данные не перезаписываются неожиданно;

сформированный результат старых URL пригоден для повторного использования.

Кроме автоматических тестов выполнить реальный пробный запуск на доступном снимке jvmoebel.de и предоставить его итоговый отчёт.

Результат задачи

По завершении должны быть предоставлены:

спецификация выбранного технического решения;

production-код backend-части SEO-миграции;

миграции базы, если они нужны выбранному решению;

команды или другой воспроизводимый способ запуска;

автоматические тесты;

результат пробного запуска для jvmoebel.de;

отчёт по обработанным и нерешённым данным;

машинный результат для старых page и media URL;

описание контракта и следующих действий для Next.js и инфраструктуры;

инструкция по повторному запуску для остальных Sales Channels;

оценка оставшихся frontend и infrastructure задач.

Критерии готовности

Задача считается выполненной, если:

SEO-данные товаров jvmoebel.de можно воспроизводимо перенести в Shopware;

происхождение данных и Sales Channel сохраняются;

старые товарные URL не теряются;

старые категории обработаны с учётом нового дерева, а не скопированы в него;

неоднозначности и отсутствующие соответствия видны в отчёте;

старые media URL и исходные файлы связаны в пригодном для инфраструктуры виде;

повторный запуск не создаёт дубли и не повреждает уже обработанные данные;

Next.js и инфраструктура получают достаточный контракт для реализации публичных URL, redirect и media;

автоматические тесты проходят;

выполнен и задокументирован пробный запуск на реальных данных Германии;

решение можно применить к следующему Sales Channel без переписывания архитектуры.

Не входит в задачу

реализация публичного SEO и страниц в Next.js;

production-настройка Nginx и redirects;

фактическое переключение домена;

работа в Google Search Console;

полное ручное сопоставление всех неоднозначных категорий;

редакционное переписывание всех SEO-текстов;

изменение целевого дерева категорий для повторения CosmoShop;

гарантия сохранения конкретных позиций в поисковой выдаче.

Эти работы выполняются следующими задачами на основе результата данной backend-реализации.
